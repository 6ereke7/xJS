xJS Feature Demo

Keep this page open and watch the browser console. Every feature and edge case below is a manual test target; the warn/error messages are the expected behaviour to check.

1. State (sm)

count = 0

Plain JS subscriber (type "normal") updating the readout on every set(). Also exercises sub() returning true.

Case: sm('missing') returns undefined (not an error).

-> check console for "missing state is undefined"

2. Derived state (compute + deps)

sm.new('first') + sm.new('last'), then sm.new('fullname', { compute, deps }).

Derived value: [fullname]

Changing first or last recomputes fullname automatically (a normal subscriber logs the recomputed value).

Case: calling set() on a dependent state throws "cannot set dependent state".

-> check console: error is thrown & caught

Case: subscriber type: "dependent" receives the State object (not the value); type: "normal" receives the value. See console under "fullname dependent sub".

3. State edge cases

sm.del(): deleting temp makes sm('temp') return undefined.

temp readout: undefined

-> create-temp then read shows the value; after del-temp, read logs "temp is undefined".

onChange(update, args): registering a side-effect callback that receives the new value plus extra args on each set().

effect: (none yet)

onChange payload logged to console as value, extraArg.

4. x-bind (text binding)

x-bind="name" → Hello, $name!

x-bind="name, missing" → $name :: $missing

The second line references the nonexistent state missing; open the console to see the warning, while $name still binds.

Case: multiple states in one x-bind.

x-bind="name, count" → $name / count=$count

5. x-model (two-way binding)

Bound with x-bind: $username

Type in the field and the x-bind text updates (input → state); click the button to set state and the field updates (state → input).

Case: <textarea> supports two-way binding too.

Case: x-model on a missing state logs a warning and is skipped without crashing.
